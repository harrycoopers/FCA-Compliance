READY FOR PUBLICATION — when authorised.

No remaining code blocker identified in the two authorised fixes. All changes remain local, uncommitted, unpushed and undeployed. Actual production hosting settings and post-deployment behaviour still need the normal release checks. Technical verification is not a legal-compliance certification.

What changed

  • Replaced the unconditional shared Google Analytics tag with one first-party consent controller. No Google library is loaded before explicit acceptance. Ads storage, ad user data and personalisation remain denied.
  • Added equally prominent Accept analytics and Reject analytics buttons, plus a footer Analytics preferences button. Rejecting through reopened preferences withdraws consent. Escape/close keeps an existing choice; it does not imply acceptance.
  • One browser-local preference key, 009.analytics-consent.v1, saves accepted/rejected until changed or cleared. Missing, malformed or unavailable storage defaults to off. If saving fails, an explicit acceptance applies only to the current page and the panel explains that limitation.
  • Guide click events use that same saved choice. Rejected events are discarded, not replayed after acceptance. Page URLs omit queries/fragments; no form values are added to guide events. No booking completion event was introduced.
  • Withdrawal sets Google's disable flag, updates consent and removes accessible GA cookies. A narrowly scoped analytics transport guard also drops previously queued measurements at send time: the real Google library was observed flushing a previously queued scroll event on navigation despite its disable flag. Same-origin login and booking requests are not blocked.
  • The tag/config initialises once per document. Repeated acceptance and same-page withdrawal/reacceptance do not duplicate page views. Other tabs and back/forward restoration honour the saved preference. Sensitive/login pages never load GA, even with a saved acceptance.
  • Updated only the relevant cookie-policy explanations to describe the actual choice/storage/withdrawal behaviour, replacing the inaccurate implication that analytics uses no browser identifiers. No paid service, dependency or new tracking provider was added.
  • Pricing's continuing-subscription paragraph now follows campaign.showPrice. The same inspection found price-specific FAQ answers and JSON-LD also bypassed that control; they now follow it too. The confirmed wording remains exact. At expiry, confirmed continuation keeps prices; unconfirmed/custom states remove unconfirmed price assertions and retain the existing neutral pricing message. No VAT, cancellation, subscription or FCA-fee terms were invented or changed.
