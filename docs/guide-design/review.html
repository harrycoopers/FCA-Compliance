A presentation-only upgrade across all 18 guide routes (17 individual guides and the hub). Existing text, links, offer terms and SEO output are preserved. Everything remains local, uncommitted and undeployed.

What changed

  • Navy and icy-blue hero composition, larger existing headings, restrained geometric background and one coordinated entrance. The title and answer remain visible throughout. A decorative check draws once; the background light pass stops after six seconds and pauses offscreen.
  • Slim reading progress, sticky desktop section panel, current-section highlighting, native expandable mobile menu and corrected fragment offsets. Existing navigation anchors and wording are retained.
  • Consistent section spacing, paper panels, pale-blue existing checklists and examples, readable comparison tables with keyboard scrolling and a mobile horizontal-scroll cue.
  • Existing related links and hub links styled as navigation cards, with matching focus/hover treatment; native FAQs and official-source links receive clearer styling. No new headings, labels, advice or links were inserted.
  • Original gift-box, Santa/referral presentation and animated booking calendar retained in their existing relevant placements. Only the surrounding layout changed; no replacement offer animation or new library was introduced.

New scoped files: public/css/guide-design.css and public/js/guide-reading.js. Small structural edits in views/seo_guide.ejs. The build appends these to the existing guide-only bundles, without adding runtime requests. Global navigation, homepage components, commercial configuration and content data were not edited for this task.

Scope and limitations

No editorial, regulatory, pricing, testimonial or metadata changes were made for this visual task. Existing guide dates were not refreshed. No new schema, indexing directives or URLs. Earlier uncommitted work remains intact. No commit, push, deployment or indexing request was made.

Checks use local Chromium, including emulated responsive widths, keyboard, reduced motion and JavaScript-disabled contexts. They are not a physical-device, Safari/Firefox or screen-reader certification. External requests were blocked in browser checks; no real bookings, reminders or emails were sent. The local development server retains its existing outbound and real-booking safeguards.

The in-app browser connection was unavailable because of its sandbox-policy metadata error; automated Playwright Chromium and the saved screenshots supplied the browser verification instead. Live previews are available at http://127.0.0.1:3100 while npm run dev is running.
